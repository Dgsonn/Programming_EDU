Content extends 125px beyond viewport on all 6 lessons. Likely from wide schema tables, concept cards, or fixed-width elements.

### Issue 2: Drag-drop broken on mobile (Playwright drag_to test)

```
Attempting drag from (75, 878) → (0, 504):
- Source: .mini-chip draggable element at y=878 (below 812 viewport)
- Target: .drop-line at y=504
- Error: Timeout 30000ms — multiple elements intercept pointer events:
  - .drag-area-head
  - #ide-code .ide-content
  - .status-text
  - nav#lesson-nav-footer
```

**Root cause:** Layout overflow causes IDE elements (Step 4) to overlap with drag-drop elements (Step 3) when on mobile. Even though step-pane has `pointer-events: none` when inactive, the absolute-positioned IDE blocks may still capture events.

### Issue 3: Small buttons (10/20 sampled buttons < 44px)

Per WCAG 2.5.5 (Target Size): buttons should be at least 44x44px for touch targets. 10-11 of 20 sampled buttons are smaller.

**3. `static/js/lesson_db_design.js`** — Logic hook (called from `goToStep`):

```js
// In goToStep, after step change:
updateMobileStep3Notice(step);

function updateMobileStep3Notice(step) {
  const notice = document.getElementById('mobile-step3-notice');
  if (!notice) return;
  // Detect touch/mobile device
  const isMobile = window.matchMedia && window.matchMedia('(hover: none) and (pointer: coarse)').matches;
  const shouldShow = isMobile && step === 3;
  notice.classList.toggle('is-visible', shouldShow);
}

// Wire up buttons
function initMobileStep3Buttons() {
  const notice = document.getElementById('mobile-step3-notice');
  if (!notice) return;
  const closeBtn = document.getElementById('mobile-step3-close-btn');
  const skipBtn = document.getElementById('mobile-step3-skip-btn');
  if (closeBtn) closeBtn.addEventListener('click', () => notice.classList.remove('is-visible'));
  if (skipBtn) skipBtn.addEventListener('click', () => {
    notice.classList.remove('is-visible');
    if (typeof window.goToStep === 'function') window.goToStep(4);
  });
}
```

⚠️ **Bug fixed during testing:** Initially used `typeof goToStep` but `goToStep` is `window.goToStep`. Fixed to `window.goToStep`.

## PHẦN 4: LESSONS LEARNED (Implementation Iteration)

### Iteration 1: `inset: auto 0 0 0` (bottom positioning)
**Issue:** In Playwright iPhone X emulation, `window.innerHeight = 1083` (not 812 as expected). `position: fixed; bottom: 0` placed notice at y=929, below viewport. Button at y=1056 was not visible/clickable.

**Root cause:** Playwright iPhone X emulation has quirk where `window.innerHeight` ≠ visualViewport.height. Possibly due to scrollbars or layout viewport vs visual viewport.

### Iteration 2: `inset: 0 0 auto 0` (top positioning)
**Fix:** Moved notice to TOP of viewport. Now visible at y=0.

### Iteration 3: Side-by-side buttons
**Issue:** On 375px viewport with Playwright's 500px layout width, buttons extended beyond visual viewport. Skip button partially clipped.

### Iteration 4: Stacked buttons (`flex-direction: column`)
**Fix:** Stack buttons vertically with `width: 100%`. Each button full-width, no clipping.

### Iteration 5: Shorter button text
**Fix:** "Bỏ qua Step 3, đến Step 4 →" → "Bỏ qua → Step 4" (fits better)

### Iteration 6: Fixed `window.goToStep` reference
**Issue:** `typeof goToStep === 'function'` returned false because `goToStep` is `window.goToStep`. Fixed to `window.goToStep`.

## §3. Code changes — ENGINE

### §3.1 `PE_parseSQLToBlocks` (lesson_db_design.js:2420+)
- **Regex mới** parse `SELECT cols FROM t1 [JOIN t2 ON c1=c2 [JOIN t3 ON c3=c4]] [WHERE ...]`. Non-greedy groups capture đúng.
- **JOIN chain split**: `var joinRegex = /\s+join\s+(\w+)\s+on\s+([\w.]+)\s*=\s*([\w.]+)/gi` → lặp `exec()` → build `parsedTables: string[]` + `onConds: {leftCol, rightCol}[]`.
- **fromBlocks rebuild**: `FROM t1 [JOIN t2 ON c1=c2 [JOIN t3 ON c3=c4]]` — keyword + table + condition mỗi JOIN tách riêng. Step-3 drag drop zones khi hydrate từ `#ide-code` sẽ match.
- **WHERE col regex**: `[\w.]+` (chấp nhận `publisher.name` qualified col). Backward-safe: unprefixed col Bài 1 vẫn match cũ.
- **Output**: thêm `_tables: string[]` + `_onConds: object[]` metadata cho executor. PE_runSQL đọc từ đây.

### §3.2 `PE_runSQL` (lesson_db_design.js:2497+)
**Resolve tables** — primary từ schema, JOINed từ `schema.related_schemas[i-1]`:

```js
var parsedTables = parsed._tables || [];
var tables = parsedTables.map(function(tableName, i) {
  if (i === 0) { /* primary từ schema */ }
  else { /* JOINed từ related_schemas[i-1] */ }
  return { name: tableName, columns, dataRows };
});
```

**Cross-product** → `{columnKey: value, ...}` joinedRows:

```js
tables.forEach(function(t) {
  t.columns.forEach(function(c, ci) {
    ext[t.name + '.' + c] = row[ci];  // prefixed ("game.pub_id")
    ext[c] = row[ci];                  // unprefixed ("pub_id") — backward WHERE compat
  });
});
```

**INNER JOIN filter** theo ON predicates (so sánh 2 cột trên joinedRows):

```js
joinedRows.filter(r => onConds.every(c => String(r[c.leftCol]) === String(r[c.rightCol])));
```

**WHERE filter** — 2 paths:
- **Single-table backward-compat** (Bài 1, 2, 5, 6, 8, 9, 16, 18): dùng `PE_parseWhereRows` (drag_game.js — A7a AND-split) y nguyên, không đổi.
- **Multi-table mới** (Bài 3, 4, 7): parse WHERE inline từ `fills['where-line']`, group `(col, op, val)` triplets, filter joinedRows. joinedRows có CẢ prefixed lẫn unprefixed keys → tra `publisher.name = 'Rockstar'` work.

**SELECT projection**:
- Phân tích alias `AS x` (`/^(.+?)\s+as\s+(\w+)$/i`).
- Non-wildcard: `outCols = projections.map(p => p.alias || p.src)`.
- Wildcard `*`: flatten `t.name + '.' + c` cho tất cả tables.

### §3.3 Bug fix quan trọng (caught bởi in-page debug)

Lần đầu dùng `{ name: t.name, ... }` thay vì `{ name: t, ... }` cho `parsedTables` (string[]). Bug: `t.name` của string là `undefined` → prefixed key = `"undefined.pub_id"` thay vì `"game.pub_id"` → ON filter lookup miss → 0 rows. Test fail Bài 3/4/7. Debug in-page (script `debug_e1.py`) reveal: tables[0].name === null, joinedRows có key `"undefined.pub_id"`. Fix đổi sang `name: tableName`.

Lesson: khi `parsedTables` là string[] từ regex split, đừng gọi `.name` (auto-add khi expect object).

## §8. Lessons learned (memory)

1. **Single-source-of-truth khi có data sẵn**: Bài 7 step_4 đã có publisher trong step_1.related_tables → COPY. Bịa data mới → JOIN FK có thể broken hoặc semantic lệch. User cứng nhắc về rule này.
2. **`t.name` của string là `undefined`**: Khi parser trả `parsedTables: string[]`, đừng gọi `.name` — đó là property của OBJECT, không phải STRING. Bug khó thấy, chỉ in-page debug với `tables.map(t => Object.keys(t))` mới reveal.
3. **In-page debug là bắt buộc khi engine pipeline đa lớp**: Test fail 0 rows → phải isolate từng layer (parse → resolve tables → cross-product → ON filter → WHERE filter → project). `debug_e1.py` trace 5 layer, in ra số rows per stage, tìm ra bug ở stage 2.
4. **Click button selector specificity**: Probe đầu dùng `text.includes('chạy')` match-first → click nhầm step-3 Run button. Phải dùng `#btn-run` (specific id) để invoke `handleChallengeRun(false)` đúng path.
5. **Multi-table WHERE inline > parseWhereRows mở rộng**: joinedRows có CẢ prefixed lẫn unprefixed keys → inline filter trên object là đủ, không cần sửa PE_parseWhereRows (drag_game.js — A7a đã ok, không touch).
